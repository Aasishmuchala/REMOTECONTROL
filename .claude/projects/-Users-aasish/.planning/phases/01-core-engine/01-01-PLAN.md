    1. Export `generateHeatmap(screenshot: Buffer): Promise<HeatmapResult>`
    2. Try DeepGaze III first (via Modal or local GPU):
       - Resize screenshot to 384x384 for DeepGaze input
       - Run model inference -> probability map
       - Resize output back to original dimensions
       - Normalize to 0-1 range
    3. U2-Net CPU fallback:
       - If DeepGaze fails (OOM, timeout, unavailable), use U2-Net
       - Same resize -> infer -> normalize pipeline
       - 1.5s timeout on CPU inference
    4. Fallback-only mode (if all models fail):
       - Return uniform heatmap (all 0.5) with flag modelFailed=true
       - Log error, do not throw
    5. Return: {heatmap: Float32Array, width, height, model: 'deepgaze'|'u2net'|'fallback', modelFailed: boolean}

    Create apps/backend/src/lib/u2net.ts:

  <action>
    Create accessibility analysis in apps/backend/src/pipeline/accessibility.ts:

    1. Export `runAccessibilityCheck(dom: string): Promise<AccessibilityResult>`
    2. Run axe-core on the DOM:
       - Configure rules: wcag2a, wcag2aa, wcag21aa
       - Include: contrast, alt-text, keyboard-nav, ARIA, forms, headings
       - Run via axe-core npm package (not CLI - use programmatic API)
    3. Custom contrast checking supplement:
       - Extract ALL text elements from DOM (tag + computed style)
       - For each: get background color + text color from CSS
       - Calculate WCAG 2.1 contrast ratio: (L1 + 0.05) / (L2 + 0.05)
       - Flag elements failing 4.5:1 (normal text) or 3:1 (large text 18pt+)
       - These supplements catch cases axe misses (in-context contrast)
    4. Score computation:
       - passCount / (passCount + failCount) * 100
       - Each WCAG failure: {id, impact, description, element, wcagRef}
    5. Return: {score: number, issues: WCAGIssue[], passedRules: string[], totalChecked: number}

    Create apps/backend/src/lib/axe.ts with:
    - axe-core programmatic API (not CLI)
    - Helper: extractTextElements(dom) for contrast analysis
    - Helper: calculateContrastRatio(fg: string, bg: string) -> number
    - Helper: getLuminance(hex: string) -> number (WCAG formula)

  <action>
    Create cognitive load scoring in apps/backend/src/pipeline/complexity.ts:

    1. Export `computeCognitiveLoad(dom: string, screenshot: Buffer): Promise<CognitiveLoadResult>`
    2. Text Complexity (textstat library):
       - Extract text content from DOM
       - Calculate: Flesch-Kincaid, SMOG, ARI, Gunning Fog
       - Combine into textComplexity score (0-100, lower is better for readability)
    3. Visual Complexity (CNN features):
       - Resize screenshot to 224x224
       - Use ResNet/EfficientNet pretrained (no fine-tuning for MVP)
       - Extract feature vector -> train small regression head
       - For MVP: use rule-based visual complexity (unique colors, element count)
    4. Layout Complexity (DOM rules):
       - Count: total DOM nodes, unique colors, unique fonts, images/text ratio
       - Nesting depth score
       - Unique stylesheet rules count
    5. Ensemble synthesis:
       - Weighted average: textComplexity * 0.3 + visualComplexity * 0.4 + layoutComplexity * 0.3
       - Normalize to 0-100 scale (higher = more complex/bad)
    6. Return: {score: number, components: {text: number, visual: number, layout: number}, breakdown: object}
  </action>

    Create visual hierarchy analysis in apps/backend/src/pipeline/hierarchy.ts:

    1. Export `analyzeVisualHierarchy(dom: string, heatmap: Float32Array): Promise<HierarchyResult>`
    2. Multi-signal fusion (5 signals):
       - Signal 1 - Size: element size relative to page (h1 > h2 > h3 > p)
       - Signal 2 - Contrast: local contrast normalization per element
       - Signal 3 - Position: F-pattern / Z-pattern detection (top-left weighted)
       - Signal 4 - Saliency: DeepGaze peaks aligned with elements
       - Signal 5 - DOM: semantic HTML tags (h1 > h2 > h3 > p > span)
    3. Per-element scoring:
       - Calculate 5 signals per element
       - Weighted ensemble: size*0.2 + contrast*0.15 + position*0.15 + saliency*0.25 + dom*0.25
       - Rank elements by hierarchy score
    4. Overall page hierarchy score:
       - Coherence: how well does element hierarchy match visual hierarchy?
       - Score 0-100: high = clear hierarchy, low = muddled
    5. Return: {score: number, elements: HierarchyElement[], coherence: number}

    Create apps/backend/src/lib/hierarchy.ts:
    - Helper: extractElements(dom) -> element list with position, size, tag, style
    - Helper: calculateSizeScore(element) -> 0-1
    - Helper: calculateContrastScore(element) -> 0-1
    - Helper: calculatePositionScore(element, viewport) -> 0-1
    - Helper: calculateSaliencyAlignment(element, heatmap) -> 0-1
    - Helper: calculateDomScore(element) -> 0-1

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input (URL) -> backend | Untrusted: arbitrary URLs, potential SSRF |
| external URL -> screenshot | Untrusted: could be malicious page |
| DOM -> analysis | Untrusted: arbitrary HTML, XSS risk |
| screenshot -> ML model | Trusted input: processed image data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | S | URL capture | mitigate | Validate URL scheme (https only), blockfile:// and internal IPs |
| T-01-02 | T | SSRF attack | mitigate | Use allowlist for capture, timeout 30s, log all captures |
| T-01-03 | I | Screenshot storage | mitigate | Store in R2/S3 with signed URLs, auto-delete after 24h |
| T-01-04 | R | Model OOM | mitigate | GPU -> CPU fallback, never block on failure |
| T-01-05 | D | axe-core XSS | mitigate | Run axe in sandboxed context, sanitize DOM before analysis |
</threat_model>
